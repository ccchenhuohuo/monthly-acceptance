# 大盘数据验收

当前发布、执行协议、政策和数据格式版本统一为 **0.0.1**。当前架构标识为 `panorama_questions`，版本编号不承担架构选择；旧冻结运行按原架构和原版本兼容。

**冻结范围 → 完整事实与客观检查 → Agent 分区判读全景 → 登记具体质量议题 → 聚合初查与按需深查 → 问题级主审 → 完成核验与报告。**

当前全景与议题架构的权威协议是 [全景、议题与审核](references/question-workflow.md)。调查使用既有 case 和 task 存储；一个具体国家×事件范围生成一条 `question_scope`。普通变化、查询分片、样本和历史来源清点不自动生成业务深查义务，也不需要逐条 defer 才能退出。旧冻结运行继续使用各自冻结的脚本与对应协议，包括历史 3.x 和 4.x；不原地升级冻结包。

程序负责范围、分页、粒度、完整聚合、身份边界、证据版本、复算与状态核验。Agent 负责数据含义、质量疑问、竞争解释和重要性；哈希不能证明 Agent 理解了数据。程序不得用数量配额、综合风险评分或固定金额门槛代替立案。30–100 只曾用于资源讨论，不是目标。

## 审计主线

先读国家、平台、数据层和完整连续月份，再读全部类目分区及其正负贡献，最后按具体疑问追到 SPU/SKU。完整 L2/L3 不得只看 Top N 或机器标记。

1. 完整性：预期国家、平台、月、层、有效类目契约及应有 raw/std 承接。查询失败、未执行、成功无观测分别保留。
2. 重复与放大：源键、映射基数、SKU/SPU 重计以及 join 造成的量额放大。
3. 身份连续性：国家+平台+父体+有效 SKU 的轨迹。NULL/空/0 SKU 保留源记录，但不得跨父体串联；跨平台同 ID 不能直接当同实物。
4. 数值守恒：同口径 raw/std、父层/叶层量额和独立去重 SPU；正负分别计算，不能用净值掩盖抵消。
5. 时间序列：完整历史轨迹、异常断点、恢复与属性漂移；没有可比旧快照就明确不能验证历史回写。
6. 价格带：同 SPU 聚合、单位/币种、数量级、跨带重复以及未知价格和空分母。
7. 历史回归：真实错误对象、时期和机制在 raw/std 与新月份的复验；展示修复不能替代底层修复。

类目打标和映射语义规则正在调整，默认不做分类正确性专项测试。纯语义争议保留历史出处或辅助观察；不得把标题/标签分歧直接升级为大盘问题。真正的丢数、重复放大、身份错联与守恒失败仍必须核查。局部问题只有在规模、销量、价格带、趋势或共同机制累计影响值得关注时才在正文单列。

## 数据口径

- 标准主表 `internal.flywheel.monthly_sales_with_dim`，raw 主表 `internal.flywheel.monthly_sales_wide_new`，均只读。标准表是分析代理，不自动等于最终发布面。
- 展示可保留 cn 合并视图；淘宝/Taobao、天猫/Tmall 必须有独立质量全景和预期范围。US/DE/JP 的 Amazon 平台同样独立核验。预期来自项目约定，观测值只用于核对平台代码，不能反推预期集合。
- SPU 用 product_id（Amazon parent_asin）。不同层级和平台的 SPU 不直接相加；国家金额分别保留本币。
- 无观测不等于零；算术守恒不证明销量真实；raw-only 不自动等于丢数，先核其是否应入 std。观察变化、已证错误影响、未解决质量风险必须分开。

## 执行

1. 读 `验收/config.yaml`、`项目范围.md` 与可用契约，明确数据月。`acceptance_run.py start --month YYYY-MM` 冻结 Skill、政策、项目和历史输入。此后用 `<RUN>/inputs/skill/scripts/acceptance_run.py`；修订冻结输入须新建运行。查询、失败重试、真实耗时和证据复用沿用现有机制，SQL 并发容量只管资源。
2. `scan`、`analyze`、`panorama-status` 导出全部事实和客观约束。需要复用原包时用 `evidence-reuse` 验证完全相同的 SQL、分页和来源；明确哪些来自旧观测、哪些是本轮在线查询。两者不伪装成事务快照。
3. 实际启动国家/风险分区阅读 Agent。用 `panorama-read` 保存其判断、完整已读范围、未读范围、关键原始定位、原始判读产物及真实独立性。先冻结独立发现，再读历史答案；读过历史的执行者不得声称盲测。普通未立案观察不逐条签“正常证明”。
4. `investigation-plan --coordinator MAIN` 建立协调身份与空的权威案件台账。主 Agent 用 `question-register` 登记质量疑问及 `scope_units`，保留反向分量、首查和停止条件。同一事件可跨月、路径和层；跨国保留独立核查范围。强约束失败必须由覆盖其实际范围的议题负责；查询错误先恢复查询。
5. `question-jobs` 生成定向聚合或完整 cohort，`question-collect` 用原生分页和自然月复用执行。先聚合；必要时才生成 `details` 完整明细。查询分片不增加业务义务。Worker 可建议范围调整，由主 Agent 版本化登记；活跃任务先保存进度再重排。不得删除路径、时期或重大反证来完成问题。
6. 主 Agent 实际启动调查子 Agent，以真实 ID `investigation-assign` 绑定完整合同。答卷按问题选择检查，不机械跑品牌/价格/语义专项。`investigation-submit` 校验并接收原始材料；主 Agent 阅读定位、复算、反证后 `investigation-review`。重大正常判断、历史回归和冲突需要未参与调查的第三人独立复核。审后合同、证据或来源变动使原审核失效。
7. 尚未回答的质量问题继续在原范围补查，不因全部市场波动缺原因解释而生成 SKU 任务。预算/时间/容量不足用 `investigation-progress` 保存真实断点，不能记作外部缺证。真实外部受阻必须指出记录、持有人、实际尝试、判断影响和恢复条件；受阻不计核实。
8. `independent-freeze` 后 `history-plan` 清点历史，`sampling-plan` 从全部适用 L3 单元分层抽样，`sampling-collect` 采集。`baseline-review` 保存样本、历史、内部对账和发布承接的实际核对与不同审核者。样本异常扩展适用检查范围并关联议题；纯语义历史仅作为有出处的辅助事项，不重建语义测试专项。
9. 所有取证后 `finish-scan`、`validate`、`render`。分别交代查询、客观检查、全景判读、议题/独立范围、真实任务/有效主审、未解决范围和实际查询/明细/重试成本。零议题可以完成，但必要检查、阅读、抽查和回归不能空缺。未完成用 `checkpoint` 保留报告与续跑；`seal` 重算门槛。报告只落盘，不自动外发或修改源数据。

## 判断边界

已证缺陷可支持打回；缺证只能形成对应限制。统计相关、标题、路径相近和编号相等都不能单独证明因果或真实身份。没有供应商/内部凭证就保留对应未知，不编造市场原因或错误影响。

详情见 [权威协议与输入示例](references/question-workflow.md)。计算口径查 [方法说明](references/methodology.md)，报告输入查 [报告写作](references/report-writing.md)，按需查 [交叉验证](references/cross-validation.md) 与 [人工 SQL 示例边界](references/sql-catalog.md)。[可视化入口](references/acceptance-guide.html) 只作导航。

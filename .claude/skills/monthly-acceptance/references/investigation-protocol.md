# 逐义务调查与实质主审协议

3.3 新运行的分类、适用调查集合和三种报告位置以 [业务分类协议](business-classification.md) 为准。原始义务保留；经审暂留不需逐项深查、不计实质核实。以下逐义务合同仅用于实际分派的任务，旧冻结运行维持原规则。
基础扫描负责找线索；本协议负责把适用调查义务转成有证据的业务回答。原始信号及义务全部保留；3.3 经主 Agent 按组审核的暂留项移出适用深查集合，保留未核实状态与复查条件，其余适用义务必须调查并主审。并行增加处理能力，不能替代证据要求。命令、机器字段和阶段门槛以本运行冻结的 [执行契约](execution-contract.md) 为准，业务计算沿用 [methodology.md](methodology.md)。

## 1. 全量义务台账，而不是一批大类摘要

主 Agent 在独立候选冻结后建立完整调查台账，并在后续发现新问题时追加。分母包括全部候选、全部明细样本、范围/键/映射守门事项、内部本品对拍，以及导入的历史重要问题和合理反例。全部月份的旧运行报告及案例库都进入来源清点义务，换验收月份不能遗失旧经验；是否同范围及本轮适用须逐项核实。历史材料尚未结构化时必须逐项迁移，不能用“没有 open-issues 文件”解释历史复验为空。历史提示在自主发现冻结后揭示；旧结论不是本轮真值。

历史来源以程序生成的 `source_material.segments` 为完整阅读分母，每段有 `segment_id / line_start / line_end / sha256`。答卷 `history_coverage` 精确重复四个定位字段，再写具体 `obligation_ids / reason` 或有据 `not_applicable_reason`，每段恰好一次。不能用自由 `locator`、文件已读、另一项文件阅读任务或一句“其余无问题”代替逐段提取；旧问题的全部月份、商品和 SKU 范围都须保留。

每个义务有唯一 ID、来源 ID、精确范围、待回答问题、责任者、证据引用、调查进度、主审记录和未完成动作。精确范围至少包含国家及平台边界、来源/标准层、完整路径及层级、观察月和比较月、涉及对象与四项指标。信号有状态或已经派发，不代表调查完成。

**按问题拆分义务，按可共用的取证合并任务。** 同一信号可以同时产生“是否重复放大”“为何增长”“是否进入发布数据”三个义务，分别完成。多个信号只有在范围、对象及比较关系一致，或具有可复核的逐项映射时，才可共享调查包：

- 同一国家、完整路径、同一对月份的销量与金额信号，可共享完整贡献表；每项问题仍分别给判断和残余。
- 同一 SKU 改挂父体的证据可以支持旧父体退出、新父体进入；不得外推为整个类目或国家进出集合的解释。
- 连续缺失月份可以共用逐月追踪表，但每个月都须证明其应采状态和实际去向。
- 环比与同比、不同层级、不同币种不可因主题相似共用一个分母或一个结论。按 L1 把数千条候选合为一句“待补证”不构成调查。

合并不得删除来源 ID。拆分必须保留父子关系和承接范围；任务失败、超时、Agent 退出或工作量过大时重新派发，未被承接的义务仍为未完成。主 Agent 每轮对账：原始义务集合与当前任务/审核集合完全对应，无遗漏、无无依据结案、无重复计数。

## 2. 主 Agent 派发，子 Agent 独立取证

主 Agent 使用子 Agent 处理有明确边界的调查包，派发内容使用 [任务简报](../assets/investigation-brief.md)。调查者与主审核者必须是实际不同的 Agent；Agent ID 是可追责角色记录，不是操作系统权限隔离。不能伪造另一个 ID 来批准自己的交付；暂时没有可用子 Agent 时保留队列，先准备可复用证据。

1. **派发前固定任务。** 指明义务 ID、范围、问题、现有证据和必须交付的核验结果；将已证事实与待证假设分开。任务大小以能逐项审核为限，不按“全部中国问题”这样宽泛的主题派发。
2. **各自工作目录。** 子 Agent 使用分配的独立目录保存 SQL、真实工具响应、计算脚本、明细和结构化交付；读取同一冻结输入。共享只读证据可以复用，必须引用原始证据身份及哈希。不得并发改写主运行的全局台账、事件文件、处置和报告。
3. **统一查询与取证约束。** 按执行契约登记查询、参数、分页、时间、返回数量、错误及输入/输出哈希。完整性有要求的查询必须取完全部结果；截断页不算完整分解。子 Agent 权限不超过本任务：只读查询，不修改数据、不外发、不自行启用未授权付费服务。
4. **逐项结构化交付。** 每个义务必须有自己的问题回答、适用范围、事实证据、反证、四项影响和残余、判断及下一动作。可以共享计算附件，不能只交一篇摘要或一组没有对应关系的证据 ID。保存尝试过但失败的路径及原因。
5. **主 Agent 导入和审核。** 主 Agent 校验引用、哈希、任务归属和完整性，再审核业务判断。只有主审可接受交付或要求返工；子 Agent 的“已完成”不直接改变整体验收状态。被退回的义务保留原交付及拒绝理由，并进入下一轮。

Agent 并发与数据库查询并发分别控制：默认最多 8 个调查 Agent，主包和所有子包共享最多 1 条同时执行的 SQL。Agent 可以并行整理、分析和审核，查询按冻结容量排队；运行器记录排队及获槽时间，失败或取消释放槽位。这个限制只覆盖当前运行及其子包，不能保证共享数据库不受其他运行影响。限流只影响执行顺序，不能删除任务或把队列变成报告结论。进度要区分排队、执行、提交、退回、已审和确有外部阻塞，不能用 Agent 数或提交数替代业务完成数。

### 沿用的基础调查命令与记录（3.2 新门槛见审核字段协议）

3.2 新增调查合同、证据行定位、复算与独立复核字段，必须同时遵守 [review-v32-schema.md](review-v32-schema.md)；下面保留共用的分派/导入/主审命令。以下均从本轮冻结的 `inputs/skill/scripts/acceptance_run.py` 执行。主 Agent 先实际创建或唤醒子 Agent，取得其真实 ID，再登记任务；CLI 不会自行启动 Agent。

| 主 Agent 操作 | 命令参数 | 记录与约束 |
| --- | --- | --- |
| 冻结调查分母 | `investigation-plan <RUN> --coordinator <MAIN_ID>` | 独立扫描冻结后生成 `investigations/plan.json`；不得换主 Agent、缩减分母或改政策 |
| 分派 | `investigation-assign <RUN> --coordinator <MAIN_ID> --agent <SUB_ID> --ids-file <IDS.json>`，或用 `--next` | IDs 文件为完整义务 ID 数组；返回 `task_id`、`attempt`、独立 `worker_dir` 及其中的 `brief.json` |
| 追加发现 | `investigation-add <RUN> --coordinator <MAIN_ID> --file <ISSUES.json>` | 每项含 `question`、`discovered_from`、精确范围和真实 `evidence_ids`，保留新增事件；不能改写原计划 |
| 导入交付 | `investigation-submit <RUN> --coordinator <MAIN_ID> --task-id <TASK_ID>` | 子 Agent 停止写入后导入其 `submission.json`；验证全部答项，登记原文件/证据哈希并归一化证据 ID |
| 逐项主审 | `investigation-review <RUN> --coordinator <MAIN_ID> --task-id <TASK_ID> --file <REVIEW.json>` | 审核绑定 `submission_sha256`；每个义务、每个 `required_checks` 都需接收或退回 |
| 退回或恢复 | `investigation-requeue <RUN> --coordinator <MAIN_ID> --task-id <TASK_ID> --reason <具体原因>` | 旧任务和答卷保留；再分派产生新任务与尝试，不能修改旧交付冒充已审版本 |
| 对账与阶段存档 | `investigation-status <RUN>`；`checkpoint <RUN>` | 前者查看全量调查状态；后者保留阶段报告并继续工作，不替代最终完成或封存 |

`--next` 生成的是调度批次，不证明同因或同范围；批次内不同问题仍须逐项回答。需要共用具体查询时优先按合法范围选取 IDs。全部中心变更由主 Agent 顺序执行；各子 Agent 可在自己的 `<WORKER>` 运行 `query`、`drill`、`diagnose --spec <SPEC.json>` 和证据归档，不能同时写主包。

自动生成的 `brief.json` 提供完整 `obligations[]`，每项的 `required_checks` 就是本任务不可缩减的检查清单。子包新证据用 `ev-…`；已在主包的证据用 `main:ev-…`。主 Agent 导入后使用归一化主包证据 ID 审核。深度调查不能只重复引用最初聚合触发证据。

`submission.json` 包含 `task_id / attempt / agent_id / answers[]`。每个答项包含原样复制的 `obligation_id / scope`、逐项 `checks`、`conclusion`、`next_action`、`business_verdict`、`repair_state`；需要四项影响的义务另填 `impact`。语义和阻塞字段见任务简报。子 Agent 不能写 `approved / main_review / reviewer_id`，也不能伪造服务端顶层 `population_proofs`。

结果变化答项还必须有 `population_proof`，包含完整 `spu_job_id`、`brand_job_id`、`sku_job_ids[]` 及 `entity_assessments[]`。子 Agent 先在其子包执行 `investigation-proof <WORKER> --candidate-id <ID> --file <ANSWER-DRAFT.json> --output <WORKER>/proof.json`，将实际生成的 `computed_impact` 填入 `answer.impact`。导入时系统根据完整 SQL、分页、双期守恒和精确 SKU 人群重新计算，不相信手写“残余为零”。完整字段与机算口径见 [执行契约](execution-contract.md)。

`raw_presence_gap / std_presence_gap` 答项必须提供 `gap_proof: {source_coverage_job_id, entity_assessments}`，由同一 `investigation-proof` 命令生成四项影响。基期从候选的完整同路径基线中选取**严格早于缺口月的最近观测月**，追到本包冻结末月；不能用缺口后的恢复月作基期，不能只追一个代表 SKU 或缺口月。`source_coverage` 必须是该范围的完整、未按商品筛选的标准诊断任务：每个基期种子 SKU × 后续自然月 × raw/std 都有精确去向、明确无观测或无法追踪的身份记录。种子 SPU 数、源行数、销量和金额须回算到基期，重复呈现的种子上下文及两层去向不能重复求和。

每个答项只接受与其信号种类唯一对应的证明：结果变化用 `population_proof`，两类路径缺口用 `gap_proof`，其他义务不附这两种字段；不能混用或同时填写，以免漏审实体。

两类证明的每个实体组都有精确且不重复的 `product_ids`、`status`（`verified / blocked_external`）、`reason / counterevidence / evidence_ids`。结果变化的 SKU 查询可以分片，缺口的完整去向任务不允许商品分片；分组核验均不能减少总体。草稿中的未调查及外部受阻实体都计入残余，零量额变化的对象也不能从 SPU 和价带义务消失。**正式提交前，两类证明均须 `cohort.not_assessed = 0`**：每个实体都已完成当前可做的内部调查；其他实体受阻不能掩盖尚未调查对象。完整轨迹只是证据，实体原因、反证和判断仍须实质审核。

SKU 为 NULL、空白或“0”时，只保留可定位的父体源记录和完整量额，不能跨父体按该占位值建立身份关系。缺口种子须标 `untraceable_seed_identity`；结果变化的目标期含此类记录时，具体 SKU 身份不能标已核。所有可做的父体、路径、量价和来源核对完成后，可用具体缺证的 `blocked_external` 答卷保留全额残余；不能删掉这些对象以满足提交条件。

查询内存失败先排查占位身份导致的错误召回及范围。合法的 SKU 商品分片可继续细分，保留原精确清单、父子分片、失败尝试、成功完整任务和仍未覆盖 ID；完成集合须等于原集合。分片取证成功不增加原因核实数。缺口 `source_coverage` 的全体种子证明不能通过只查部分商品规避。

缺口四项残余以完整基期暴露计算：SPU 数、各固定价格带未核 SPU 占完整基期总体的比例、按商品汇总的基期量额绝对值。无观测不等于零销售，更不能把这份暴露写成缺口月损失。缺平台/SKU 身份的种子无法证明去向，不能标为 `verified`；已完成内部调查但确有外部缺证的实体保留残余和阻塞，仍不满足最终完成门槛。

主审文件包含 `reviewer_id / submission_sha256 / obligations[]`。每项含 `obligation_id`、`decision`（`accept / return`）、`reason`、`scope_check`、`check_reviews` 及 `evidence_checked`；每个检查也有 `decision / reason`。含 `population_proof` 或 `gap_proof` 时另填 `entity_reviews[]`，每组的 `assessment_sha256` 是**导入后**完整实体判断对象的 `acceptance_core.digest(group)`，必须覆盖全部实体组；接受义务时各组 `decision` 都须为 `accept`，并记录实际核查原因与反证的理由。任何组不合格就退回该义务。接受前核对全部动作、总体机算、实体判断及影响数值证据，不能只签整个任务。主审接受且存在受阻检查时，该义务结果为 `blocked_external`，不是 `verified`。

3.2.0 以此调查台账和主审为业务调查完成记录，并独立核验必查、历史回归、抽查和案件完整性；不再要求另抄旧 `record / sample-reviews / historical-recheck / internal-reconciliation` 索引，也不能让旧索引替代新证据。旧版本仍按其冻结契约读取。

历史来源主审另需 `history_segment_reviews[]`，逐段填 `segment_id / decision: accept / reason`，覆盖全部冻结段。主 Agent 核查该段实际包含的事项是否全部进入具体义务，或不适用是否成立；不合格就退回，不以段落数相同推定理解正确。历史总体尚未导入的专门义务，还须用 `imported_obligation_ids / inventory_reconciliation` 证明逐对象承接。

## 3. 每条已分派义务的必经调查

以下动作按问题适用，不相关项须说明有据的不适用原因；不能跳过共同的范围、影响和主审要求。

**先重建事实与分母。** 核对国家、币种、自然月、公司标准完整路径及对应子体，重算前后期 SPU、固定价格带、销量和金额。无观测与零值分开，未知价格单列。上级 SPU 重新去重；层级不叠加，同一父体跨类目只汇总属于该类目的子体。完整键、映射放大或计算不守恒先核实，再解释业务变化。

**再定位全部变化，返回具名对象。** 取得双期完整细分类目、品牌和 SPU 分解，保留未识别品牌及进入/退出/持续集合。品牌必须有名称、对象 ID 和分量，不能仅返回正负变动总额。销量和金额分别核对正向、负向贡献与净变化，检查抵消；净变化很小时使用绝对变动和基期规模，不能用不稳定的净贡献比决定优先级。

**安排 SKU 核验的先后。** 优先处理两期销量头部、金额头部、量额绝对变动贡献者的并集，以及价格带迁移、进出集合、关键品牌和历史高影响对象；完整总体实体均由机器核对；有适用且经独立验证的规则可共享证据履行具体检查，剩余对象再派调查，不要求每个信号机械重复相同取证。保留所有未展开对象的四项残余，不能只查头部。销量头部不能被低金额排除，旧头部不能被只看当月排除。固定明细样本另行核身份、量价、源映射结构及影响，不能代替全盘与变化贡献调查。分类规则语义不做默认专项，只有明确的大盘影响证据或用户指定时才登记。

**追踪身份、量价与来源。** 对重要对象按相关月份展开原始 SKU、标题、售卖物、规格、套装件数、单位、父子关系和完整路径；脉冲或断点应含前后相邻月份，年度变化要包含两年对应月及必要连续期。检查同父体换规格、同 SKU 改内容、换父体但子体延续、价格字符串/币种变化。缺失对象必须跨全部原始路径查去向，不能只在当前标准类目找。真实新品、历史回归、采集变化、映射变化和身份变化分别量化。

**检验竞争解释并算未解释部分。** 根据对象和时期检验数据机制与市场机制，保留支持和反证。季节、活动、上新、渠道迁移或宏观变化须有与具体商品及时间相符的传导证据；一个节日名、一条同向新闻或相近的第三方估算不能证明异常幅度。外部方法和内部同源限制见 [cross-validation.md](cross-validation.md)。

**把原因与缺陷分别记账。** 一件商品错分，只证明该商品的缺陷。它对类目量额有多大影响、其他商品为何变化，须继续核实。对可信纠错值计算两期纠错影响；仅排除疑似集合时，两期采用同一规则并标明敏感性分析，不称修复后真实规模。因果解释可能重叠，不把互相关联的原因贡献简单相加。

## 4. 各类问题必须补齐的证据

| 问题 | 不可省略的核验 | 可审核的交付 |
| --- | --- | --- |
| 量额、SPU、价格带变化 | 双期完整具名分解；正负抵消；旧/新头部；重要 SKU 身份量价；剩余群体 | 可还原父类目结果的分解、证实/未证对象、四项残余和使用影响 |
| 原始/标准路径缺失、采集断点 | 有效期内应采契约；缺口前最近观测月完整种子跨路径追至包末；每个 SKU × 后续自然月 × raw/std 去向；迁移/回归/新增/映射分解 | `gap_proof` 回算基期 SPU/源行数/量额，全部实体原因及反证、节点与有效期依据；基期暴露不冒称缺口月损失，同名叶子不能消除合同疑点 |

| 内部本品、指定关键品牌 | 独立列品牌任务；同国家、平台、期间、SKU、售卖单位、退货和币种对齐；核对未匹配项与同源校准 | 具名品牌及 SKU 差异表、可复现的口径桥接、限制；缺内部数据保留具体阻塞，不以市场总量代替对拍 |

## 5. 何时能结束调查，何时只能交付阶段结果

每个义务分别记录**调查进度、业务判断和修复进度**。业务上支持某项解释，不等于源数据已修复；发现缺陷不等于全部变化已解释；证据包已接收不等于问题已核实。

- **有证实质结论：** 对象、范围、证据和影响足以回答该义务；结论限于证据支持的部分。缺陷可记为调查已证实、待返修，只有修复并复验后才能称已关闭。
- **已核验的低影响残余：** 所有信号均先完成适用核验，再依据冻结规则核算剩余 SPU 数、价格带结构、销量、金额。四项都须有可重算的量化依据且满足停止条件，无合同范围、关键品牌等例外，主审才可接受停止继续细挖。3.2 试运行使用冻结的 1% 比例和 0.5pp 带结构调查容差，仅适用于完整机诊且剩余可界定的情形；它们尚未校准为业务误差许可。低影响未核保留明确复查条件与剩余原因状态，不计为已解释。低优先、金额小、只解释了金额头部或“样本看起来正常”均不是停止理由；不得临时改阈值过关。
- **有证据的外部阻塞：** 已做完当前权限和证据下可执行的内部核对，明确缺少的对象/月份/字段、所需来源、已尝试动作及真实结果、为何这份证据不可替代、受影响判断和下一动作。没有执行内部工作、查询暂时失败或任务量大不算外部阻塞。
- **其余均为未完成：** 通用的“需服务商确认”“市场原因待核”不满足交付门槛，须返工或继续执行。外部阻塞即使主审确认属实，仍未证明原因，不能计入实质核实率或用于全量放行。

四项残余附件至少列前后值、未解释集合及其 SPU 数/占比、各固定价格带的 SPU 与金额结构、销量/金额存量和增减影响、计算口径及证据。一个净变化比例不能代替全部残余；相互抵消时另列正负变动。所有低影响信号都必须有对应记录，集中呈现不等于跳过。

## 6. 主 Agent 审核须回到数据

主 Agent 对全部交付逐义务审核，可使用程序批量重算和关联校验，不能只读子 Agent 摘要或只抽查部分任务。审核至少回答：

1. **对的是谁？** 来源 ID 全部对应，国家、平台、月份、比较关系、路径层级、品牌、SPU 和 SKU 没有偷换；引用真实有效且覆盖相应范围。
2. **算的是哪个分母？** 从明细重建关键值，量额分解守恒、SPU 去重、价格带和未知值正确；无分页截断、重复映射、跨层叠加或跨币种求和。
3. **证据回答了问题吗？** 缺陷事实、变化解释、采集/映射与发布影响分别有依据；竞争解释经过检查，主张没有超出证据；单个反例没有代替全类目调查。
4. **还剩多少没解释？** 四项残余覆盖未展开和未证实对象；继续动作具体；低影响符合事先规则；外部阻塞确实已穷尽内部可做工作。
5. **能进入报告吗？** 判断、使用限制、返修/补证请求与证据一致。保留接收或退回原因及对应证据、提交版本；返工后重新审核，不能沿用旧接收状态。

审核发现遗漏或新疑点时追加/拆分义务并重新派发。关键数值或对象不一致、范围替换、缺少反证或残余、泛化结案、未穷尽内部动作的阻塞，均退回。主 Agent 负责最终结论，不能以“子 Agent 已确认”作为证据。

最终分别显示基础扫描、全信号调查、主审、实质核实、外部阻塞和缺陷返修进度。未派发、未提交、退回未改、未审或内部动作未完成时，整体调查未完成；全部可做调查完成但仍有真实外部阻塞时，只能交付明确受限的阶段结果。3.2.0 对未完成调查拒绝最终 `seal`，使用 `checkpoint` 保留可继续的阶段记录。历史 v3.0 包可能已将受限结果封存；那只固定旧运行状态，不能证明完成，也不能套用为本版的收尾标准。

## 7. 用实际漏例与反例验证改造

至少回归：低金额高销量镜头盖、整机混入桌面支架、具名品牌神牛变化、日本历史器材包、同 SKU 历史统一价格、采集断点与回归集合、跨平台同 ID、套装变化和子体改挂反例。要求重新定位具体对象与问题，只有同类目触发信号不算召回。样例只校准方法，不能把固定商品 ID 当通用召回规则。

除计算正确性外，测试必须拒绝“所有 ID 都填待证即完成”“一个错分样本关闭整个变化”“同 L1 不同月份批量共用一句解释”“子 Agent 提交即算主审”“遗漏普通优先级义务”及“没有具体缺口的外部阻塞”。比较独立运行的对象、问题、证据边界和使用结论，同时检查共同漏项；记录数据重放一致只能证明计算稳定。

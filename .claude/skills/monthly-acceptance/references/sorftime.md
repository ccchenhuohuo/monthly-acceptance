# 外部交叉验证（Sorftime）

内部证据链是验收主体。只有三个前提同时成立才调用：站点是 Amazon（淘系没有外部参照）；内部证据已用尽仍分不清“数据缺陷还是真实市场变化”；外部答案能改变定性、优先级或置信。纯市场研究走受治理的 flywheel 通道，不用 Sorftime 替代或“修正” flywheel 的数。

## 成本纪律

- 工具是本地 CLI `sorftime-team`（凭据由 CLI 托管）与 `sorftime-research` skill（需显式调用，刻意不自动触发）。
- 额度是全团队共享池。非免费调用先向用户报端点、站点、对象和预估消耗，得到同意再调；`--allow-coin`、`--allow-write` 永不自行开启。
- 查计费：`sorftime-team endpoints --group <组>`；查余额（免费）：`sorftime-team account request-stream`。价目以当前帮助为准；带趋势且窗口超过 15 天的单 ASIN 查询按 2 次计（2026-09-04 实测），报价前先确认计费细则。
- domain 映射：US 1、DE 3、JP 7、MX 10、BR 13。

## 取证与解释

1. 先缩小问题再调用：是范围漏采、路径迁移、父子体归属，还是主要贡献商品的量价趋势？单 ASIN 核查最便宜，优先用它。
2. 对齐口径：国家、父体 / 子体（一个子体不代表整个 SPU）、日历月与滚动 30 日（趋势字段是滚动 30 日，取月末观测点对齐日历月）、币种、指标定义、更新时间。
3. 趋势字段是扁平的“日期, 数值”交替数组（`[20260501, 760, 20260502, …]`），两两配对解析；空结果先查结构再下结论。
4. 核对来源独立性：服务商历史上用过 Sorftime 补数或校准（交接反馈第 76 行），相符只证明口径一致，不是独立真值。
5. 空响应、无权限、查询错误、端点不覆盖与真正无观测分别处理，都不当零。
6. 结论守住“只作佐证不作裁决”：写明样本量、方法差异与支持 / 削弱了哪项解释；分歧提示继续排查，不直接认定任何一方错误。
7. 把查询对象、口径、消耗与结果保存进运行目录（`queries/` 下另存 JSON），报告里注明位置。

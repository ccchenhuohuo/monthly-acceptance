# 十二个检查模块

每个模块每期都要给出状态：✅ 已查、未见问题 / ⚠️ 有问题（写进重点问题或需服务商核对）/ ⏸️ 没查成（写原因与补查条件）。摘要文件只负责把全量结果摆出来，标记是固定规则的初筛，判断与下钻靠你。下钻模板在 `sql/drill/`，参数写在每个文件头，用 `scripts/q.py RUN --name <名> --file <模板> --param K=V ...` 执行。

## 1. 到货与完整性 — `digest/01_到货与水位.md`

- 看：每个国家×平台全部月份是否都在；新月的行、SPU、件、额与历史同量级；历史月有没有推丢（缺月）或推薄（行数、SPU 骤降）；无效值行。
- 判：缺月、推薄是硬问题；BR/MX 2025-10 之前无数据是正常。服务商可能分波推送，未到的站点写“待到货”，下次补验。

## 2. 站点水位 — `digest/01_到货与水位.md`

- 看：行 / SPU / 件 / 额四条线的环比、同比；“台阶”“量动身份不动”“违季节”标记；关注件占比是否突变（打标口径变化也会表现为关注件跳变）。
- 判：先定基调再进类目。台阶要接着用模块 3 区分覆盖与估算；量动身份不动是估算摆动候选；违季节要结合当年大促实际日期。cn 合计表只作展示。链接数、SKU 数单月凹陷而件额与头部正常，且服务商口径里说明过这种行为的，标“已说明的口径行为”、不进问题清单；影响头部或销售额时照常当问题（methodology 第 6 节）。

## 3. 覆盖变化还是估算变化 — `digest/02_覆盖估算与长尾.md`

- 看：TOP100 / TOP1000 占比、固定集合次月变化与上年同期、集合消失数；关注口径的新增 SPU 件占比、留存件环比 / 同比、消失件占基期。
- 判：占比台阶下降且不回升 + 增量来自新增 = 覆盖扩大；固定集合与留存商品同步偏离（扣除 -5%~-9% 排名回落与季节基线后仍显著）= 估算变化。覆盖变化导致总量与 SPU 数跨期不可比，头部口径仍可比；估算变化连头部都不可比。

## 4. 标准类目四项结果 — `digest/03_类目四项结果_一级.md`、`digest/04_类目贡献与异常.md`

- 看：一级类目的件、额、SPU、均价的环比同比与 13 个月走势；二三级子类对父类变化的贡献（件、额两条线）；全历史三级叶子异常（稳健 z 分、出现 / 消失），并对照同月站点级标记；单品对一级类目的影响（占类目件额、对类目环比的贡献、剔除后的类目环比）；单品对小类的影响（近三个月占小类金额 ≥15%，不看涨跌）。
- 判：优先查会改变类目趋势方向 / 幅度、主要价格带或 SPU 规模判断的局部变化。叶子异常与站点台阶同月 = 多半是站点事件的一部分；叶子自己动 = 下钻 `spu_changes.sql` 看驱动商品，必要时 `spu_trace.sql` 看轨迹。少数商品解释大部分涨跌时先查它们的打标、量价与身份：单品占类目 ≥25% 或主导类目环比的，先核对标题、品牌、平台路径是不是同一件商品；单品大幅变动且有反向的同品牌商品，先查是不是换了身份。小类里撑起小类、单价远高于小类中位数、或挂在小类主体以外平台根节点下的商品，先看标题是不是整机进了配件叶或别的品类混了进来，按金额算对小类的影响。

## 5. 价格 — `digest/05_价格.md`

- 看：跳价计数（约 10 倍、≥50 倍）、影响最大的跳价明细、价格带份额迁移、落在分带外的商品、跟同类比的离群价（近三个月均价 ÷ 小类中位数；“-其他”叶单列，只看占该叶 ≥1% 的商品）。
- 判：约 10 倍优先当位数错误核实；带外高价先看标题排除真贵货。离群价抓的是一直错、从没跳过的价格：≥50 倍先当占位价或位数错误核实，20–50 倍先排除真贵货和错分的整机。确认的错价按“错价 × 件数”量化对类目金额的影响，说明是否改变类目金额走势或价格带结论。

## 6. 长尾 — `digest/02_覆盖估算与长尾.md`

- 看：≤5 件 SPU 占比、件数中位数的月序列与“长尾占比”标记。
- 判：总量降而头部稳、尾部占比骤变 = 长尾截断或拟合口径变化；它还能兜住总量网格漏掉的温和扩容（商品数大涨而总量只小涨）。尾部单月变薄而件额正常、服务商口径里有说明的，属已说明的口径行为（同模块 2）。

## 7. 品牌层 — `digest/07_品牌.md`

- 看：OTHERS/其他 占比（关注口径内与治理层指标）、一级类目品牌数突变、品牌增速与类目增速背离、件数 / 金额双口径前五；品牌清洗核对（原始品牌 → 标准品牌对不上、有名字的原始品牌进了 OTHERS、同一品牌多个标准名、只差大小写的标准名、片假名标准名、不像品牌的标准名）；二级类目 OTHERS 的同比；各小类金额前五品牌。
- 判：背离后用 `brand_churn.sql` 拆新增 / 留存 / 消失。对不上的金额大的，查是不是按子串归并、把不相干品牌并了进来；同一品牌拆成几个标准名的，品牌份额要合并看；小类头部品牌不属于这个小类的，交叉看打标（多半是错分的商品带进来的品牌）。品牌数单月暴增后回落常与幽灵商品同源；OTHERS 占比上升意味着具名品牌份额被系统性低估，影响竞品分析，要写给服务商。

## 8. 平台类目树 — `digest/08_平台类目树.md`

- 看：最新月新出现 / 消失的平台路径、中途断档路径、采购范围前缀逐月是否有数据、范围外路径里的关注件。
- 判：缺数月份先核对范围文件的写法与生效期（scope.json 的说明列），再判漏采。范围外出现大量关注件，说明实际采集与采购范围文件不一致：要么范围文件过期，要么服务商超范围采集，都写给用户确认。定性（改版 / 断层 / 改名 / 新路径 / 待观察）后追加 `验收/类目树变更台账.md`。

## 9. 打标质量 — `digest/09_打标质量.md`，方法见 `references/tagging.md`

- 看：结构合法、无标签、“其他”分流候选、跨月换叶、残差叶占比、属性填充率、叶子的平台类目构成、小类里挂在少见平台根节点下的商品、抽样样本（件数前 3、金额前 3、贵价、打散）。
- 判：按判定标准逐条判样本与变化驱动商品，计法统一（见 tagging.md），判完用 `tagging.py` 汇总；读叶子构成时对照叶子定义，明文排除的商品挂在哪些平台节点、占整叶多少，不等抽样就能看出来。错分改变类目四项结果判断的单列为重点问题，其余汇总为打标质量指标与需服务商核对的清单。判定文件里成片的不符必须进报告并按整叶量化（规则见 tagging.md）。

## 10. 本品对拍 — `digest/10_本品.md`

- 看：本品在各站点各类目的件、额份额与走势；内部数据是否投递。
- 判：本期发现的问题有没有污染本品数字（按站点分别回答）。内部数据到位时销量对销量优先、金额参考。先读服务商口径里本品销量与退货的处理方式，判断对拍是独立验证还是循环验证：循环的对得上是设计如此，对不上才是信号；退货口径不同造成的系统偏差属预期。服务商若随推送附了对数文件，可直接对照。未投递写 ⏸️。

## 11. 治理承接 — `digest/11_治理承接.md`

- 看：现役发布 dws 聚合与源表关注口径逐格对账（仅一边有、量额或行数不等）；治理层覆盖率指标。
- 判：不一致要查清是发布版本错位（发布基于旧上游）、过滤规则还是重建问题。源表在发布之后更新过时，提醒治理层需要重建（重建不在本 skill 内）。

## 12. 已知缺陷复验与服务商对账 — `digest/对照_已知缺陷.md`、`digest/对照_服务商.md`（第 6 步才读）

- 看：已知缺陷台账每条对象在本次数据里的标准路径轨迹与量额；上期报告的需服务商核对事项；沟通台账里未闭环的问题及其对象的最近观测；本期冻结的服务商增量（群聊新消息、客户反馈清单的新增与变动）。
- 判：仍在错误路径 = 未修复；已离开 = 核对去向是否正确；未观测 = 不能判断，先核对登记本身：站点、父体还是子体、编号写法（群里常把 B0 写成 BO）。复验结论更新进 `验收/已知缺陷台账.json` 的 status 与 facts。上期事项逐条对账（上期提出 → 服务商回复 → 本期是否修复），写进报告“上期事项对账”一节；台账问题逐条复验，“服务商称已修复”也要看本期数据。复验结论与增量里新的事件↔回复配对，写进 `RUN/服务商台账更新.md`，用户确认后再并入沟通台账。

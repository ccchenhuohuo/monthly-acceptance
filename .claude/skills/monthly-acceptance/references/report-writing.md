# 从全景到业务议题的报告（0.0.1）

执行与字段门槛以 [问题协议](question-workflow.md) 和本运行冻结脚本为准。报告骨架见 [报告模板](../assets/report-template.md)。

先交代国家、平台、连续月份与 raw/std 的实际覆盖，再说明影响大盘判断的质量问题。每个重点问题在同一处讲清：观察到了什么、完整分母和影响是什么、哪些证据与反证支持判断、还缺什么及下一步。SPU/SKU 明细用于证明机制，完整清单放证据包。

普通市场波动没有原因解释，不构成待调查债务。类目语义争议不做专项；纯语义历史保留出处或辅助处置。映射导致丢数、放大、错联或守恒失败，仍按实际质量问题处理。不得为达到问题数量或金额阈值而立案、撤案。

## 正文输入与生成

当前 `render` 读取 `<RUN>/report-content.json`。`summary` 是字符串数组；`findings` 中每条绑定当前 `case_id`、`case_version` 和该议题的 `obligation_ids`，已主审结果与外部阻塞均须承接。报告位置由议题台账的 `report_placement: main / brief / appendix` 决定，不在报告里另外分类。

每条 finding 使用 `assessment`、`observation_change`、`proven_error`、`unresolved_quality_risk`、`counterevidence`、`next_check`、`evidence_ids` 表达结论。观察变化、已证错误影响、未解决质量风险分别说明，不把同一观察金额重复当成错误与风险。身份与币种边界、正负抵消、基期和计算分母贴近相应数字。

程序输出 `报告.md`、`execution-metrics.json`、`resume.json`；`checkpoint` 另保存续跑状态。当前全景与议题架构不生成旧版 `audit.html` 看板，也不使用旧 `candidate_ids`、`presentation`、原因解释率或 `case-acknowledge-review` 作为报告流程。七类检查的覆盖与能力限制来自全景和基础审核；若在摘要展开七类概览，必须引用实际结果，未查不写正常。

## 完成度与业务使用

分别列查询任务、事实单元、客观检查、全景阅读分区、业务议题、独立调查范围、实际分派、有效主审和待查。它们不能互换分母，也不能用议题压缩比推算成本或完成率。

| 状态 | 可作的表述 | 限制 |
| --- | --- | --- |
| `verified` | 问题范围已获有效主审；缺陷与使用判断另列 | 不自动等于正常、已修复或放行 |
| `blocked_external` | 主审确认具体缺证、实际尝试及恢复条件 | 计入已主审，不计核实和完整验收 |
| 排队、执行、待主审、退回、容量待续 | 原问题仍待回答或审核 | 不能写成外部缺证或已完成 |

当前全景与议题架构没有通用 `reviewed_residual` 完成分支。未回答的质量疑问继续原范围；没有市场原因解释本身不延长调查。未完成的报告在开头明确阶段状态与重要限制。工程验证通过和少量业务议题试查，均不代表整月验收通过。

每个判断保留国家、平台、对象、月份、来源、合同/答卷/主审版本。跨国金额分别保留本币；SPU 不跨平台或层级直接相加。敏感性排除不等于修正后真实市场。历史独立发现与清单引导复验分别计数；当前原始数据不能证明历史未被回写。

仅披露实际请求、成功/失败、复用、重试、排队和计时边界；模型 token/费用未取得时写未知。归档复用不算新查询，相同指纹不等于事务快照。报告只落盘，外发或改源数据须有用户授权。
